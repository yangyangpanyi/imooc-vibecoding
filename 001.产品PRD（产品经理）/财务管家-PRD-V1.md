## 1. 产品概述

### 1.1 背景与问题

多数人每天都有消费，但记账产品的最大障碍是**「坚持不下来」**：录入步骤繁琐、分类混乱、看不到记账带来的价值，用几天就放弃。现有产品要么功能臃肿、上手成本高，要么只服务个人、无法覆盖家庭共享和个体户的简单经营场景。

### 1.2 产品定位

一句话：**一款「打开就能记、记了就有用」的轻量记账工具。**

- 录入：3 步内完成一笔（金额 → 分类 → 确认）。
- 价值：立刻反馈「今天/本月花了多少、花在哪、还剩多少预算」。
- 轻量：不做预算外复杂功能，专注「记」和「看」。

### 1.3 目标用户

| 群体 | 特征 | 核心诉求 |
| --- | --- | --- |
| 普通个人（主力） | 18 岁以上，有记账意愿但怕麻烦 | 快速记账、看清钱花哪了、控制支出 |
| 情侣 / 家庭 | 两人及以上共享开支 | 一起记、共同看、分清谁花了谁出钱 |
| 个体户 / 小微企业主 | 经营与生活账混在一起 | 简单区分经营收支、能导出报表对账 |

### 1.4 核心价值

1. **低门槛**：极简录入流程，支持无分类快速记、事后补分类。
2. **即时反馈**：首页即呈现「本月总览」，记账立刻见效。
3. **数据安全**：账号 + 云端存储，换设备不丢数据。
4. **可扩展**：架构预留「多账本」，个人 / 家庭 / 经营三类场景统一承载。

### 1.5 版本规划

| 版本 | 目标 | 关键能力 |
| --- | --- | --- |
| **V1（本次）** | 跑通个人记账闭环 | 账号、记账、账户/分类管理、账单、统计、预算、导出 |
| V1.x（增量） | 覆盖共享与多账本 | 共享账本（家庭/情侣）、多账本、周期记账 |
| V2 | 覆盖经营 + 全端 | 小微企业经营记账、移动 App、小程序 |

## 2. 范围

### 2.1 V1 范围内（In Scope）

- 账号体系：注册 / 登录 / 登出（手机号或邮箱 + 验证码）
- 记账：收入、支出、账户间转账
- 账户管理：默认账户（现金、银行卡、支付宝、微信）+ 自定义
- 分类管理：内置默认分类 + 自定义分类（支持收入/支出分类）
- 账单：明细列表、按时间/分类/账户/收支类型筛选、关键词搜索
- 统计：总览、分类占比、收支趋势、月度对比
- 预算：总预算与分类预算、超支提醒
- 数据导出：CSV / Excel
- 云端存储与多设备同步

### 2.2 V1 范围外（Out of Scope）

- 共享账本 / 多成员协作（→ V1.x）
- 多账本（→ V1.x）
- 周期记账、记账模板（→ V1.x）
- 经营记账：应收应付、客户/供应商、发票、税务分类（→ V2）
- 移动 App、小程序（→ V2）
- 多币种、数据导入（→ V2）
- 社交/社区、理财建议、自动同步银行流水

## 3. 用户画像与核心场景

### 3.1 画像

**A：上班族小李（主力）** 26 岁，月薪固定，想攒钱但总「不知道钱花哪了」。诉求：随手记、月底看分类占比、设预算提醒自己别超。

**B：情侣小张和小陈** 30 岁左右，同居、日常开支混着花。诉求：两个人往同一个账本记账、月底看共同支出。

**C：个体户王姐** 35 岁，开小餐馆，经营和个人开销混在一个微信里。诉求：把进货、营业收入和个人消费分开记，月底导出给会计。

### 3.2 核心场景（用户故事）

1. **随手记账**：小李买咖啡，打开网页 → 输入 32 → 选「餐饮」→ 确认，3 秒完成。
2. **月底复盘**：小李看「本月统计」，发现餐饮占比 40%，决定下月设 1500 餐饮预算。
3. **超支提醒**：预算剩余不足时，首页/通知提醒小李控制支出。
4. **一起记账**（V1.x）：小张小陈共享账本，各自记录，月底看共同结余。
5. **经营对账**（V2）：王姐开「经营账本」，记进货成本和营业收入，导出报表对账。

## 5. 功能详细说明

### 5.1 记账（核心功能）

**入口**：全局常驻「记账」按钮（底部导航中间，移动端拇指可达）。

**流程（3 步）**：

1. 选类型：默认「支出」，可切「收入」「转账」。
2. 输入金额 + 选分类：金额用大数字键盘，分类默认给常用分类（最近使用置顶），支持跳过分类先记。
3. 确认：可选填备注、账户、日期（默认当天）、成员（V1.x）。点击「保存」完成。

**规则**：

- 金额支持最多 2 位小数；收入/支出金额必须 > 0。
- 转账不选分类，只选「转出账户 → 转入账户」。
- 未选分类的流水标为「未分类」，账单页提供批量补分类入口。
- 保存成功后轻提示「已记账」，可一键「继续记」。

**异常处理**：

- 无账户时引导先创建账户。
- 金额为 0 或空时「保存」置灰。
- 网络失败时本地暂存，恢复后自动同步（依赖 PWA 离线能力）。

### 5.2 账户管理

- 默认账户：现金、银行卡、支付宝、微信。
- 支持新增、重命名、删除账户；删除需确认（账户有流水时改为「停用」而非物理删除）。
- 每个账户可设**初始余额**，账户余额 = 初始余额 + 该账户收入 − 该账户支出 + 转入 − 转出。
- 首页展示「净资产」= 所有账户余额之和。

### 5.3 分类管理

- 内置分类（支出）：餐饮、交通、购物、居住、娱乐、医疗、教育、人情、其他。
- 内置分类（收入）：工资、奖金、理财收益、兼职、其他。
- 支持新增、重命名、删除（有流水的分类删除后，历史流水归入「其他」）。
- 支持设置分类图标与颜色，便于图表辨识。
- 支持二级分类（如「餐饮 → 早餐/午餐/外卖」，V1 可选）。

### 5.4 账单明细

- 默认按天分组、时间倒序，展示当天收支小计。
- 每条流水展示：分类图标、备注、账户、金额（支出红/收入绿）。
- 支持编辑、删除单条流水（删除需二次确认）。
- 筛选：时间范围（今天/本周/本月/自定义）、收支类型、分类、账户、关键词。
- 支持按筛选结果查看小计（收入合计、支出合计、笔数）。

### 5.5 统计与分析

- **总览**：本月/本年的收入、支出、结余，与上月/去年环比。
- **分类占比**：饼图，支持按收入/支出切换，点击查看某分类明细。
- **收支趋势**：近 6/12 个月折线图，收入 vs 支出。
- **账户余额**：各账户余额分布。
- 所有图表支持切换时间范围（本月/近 3 月/今年/自定义）。

### 5.6 预算管理

- 支持设置**总预算**（如月支出 5000）和**分类预算**（如餐饮 1500）。
- 进度展示：已用金额 / 预算额度 / 剩余，进度条变红表示超支。
- 剩余不足 20% 与超支时，首页与记账时给出提醒（站内通知，非推送）。

### 5.7 账号与数据

- 注册：手机号或邮箱 + 验证码，设置昵称。
- 登录：验证码登录为主（免密，降低门槛），第三方登录 V1 可选。
- 登出后本地不残留敏感数据。
- 所有账务数据云端加密存储，多设备登录自动同步。

### 5.8 数据导出

- 按时间范围（或当前筛选结果）导出 CSV / Excel。
- 导出字段：日期、类型、分类、金额、账户、备注。
- 供用户对账 / 备份，也为个体户 V2 经营对账打基础。

## 6. 信息架构与页面结构

```
底部导航（移动端 4 Tab）
├── 首页（总览）：本月收支/结余、净资产、预算进度、最近流水、快捷记账
├── 账单：明细列表 + 筛选/搜索
├── 记账（中间凸起按钮）
└── 我的：账户、分类、预算、统计、数据导出、设置、关于

「统计」入口：首页「查看统计」进入，或「我的」进入
```

**移动优先**：所有页面先按手机屏幕（375px 宽度）设计，桌面浏览器自适应加宽，不做桌面专属交互。

## 7. 数据模型概要

核心实体（为多账本预留 `book` 字段）：

```
User          用户：id、手机号/邮箱、昵称、创建时间
Book          账本：id、owner、name、type(个人/家庭/经营)、成员[]   ← V1 单账本，V1.x 扩展
Account       账户：id、book_id、name、type、初始余额、状态(启用/停用)
Category      分类：id、book_id、name、type(收入/支出)、父分类、图标、颜色、排序
Transaction   流水：id、book_id、type(收入/支出/转账)、金额、category_id、account_id、
                    transfer_to_account_id(转账)、备注、日期、成员、创建/更新时间
Budget        预算：id、book_id、period(月/年)、scope(总/分类)、category_id、额度
```

## 8. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 首屏 ≤ 2s；记账操作响应 ≤ 500ms；账单列表滚动流畅（虚拟列表） |
| 兼容 | 主流手机浏览器（iOS Safari、Android Chrome/微信内置浏览器）、桌面 Chrome/Edge |
| 安全 | 全站 HTTPS；密码/验证码安全存储；账务数据加密传输与存储 |
| 隐私 | 不采集非必要信息；数据仅用户本人可见；提供账号注销与数据导出 |
| 可用性 | 移动端触控目标 ≥ 44px；核心操作 ≤ 3 步；错误有明确提示 |
| PWA | V1.1 起支持添加到主屏、基础离线记账、网络恢复后同步 |
| 可维护 | 前后端分离，接口文档化，数据模型预留多账本与多成员扩展 |

## 9. 数据指标（成功指标）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 记账成功率 | 完成一笔记账 / 发起记账 | ≥ 95% |
| 记账耗时 | 从打开到保存一笔 | 中位数 ≤ 10s |
| 次月留存 | 首记后下月仍在记账 | ≥ 40% |
| 日均记账笔数 | 活跃用户日均记录笔数 | ≥ 2 笔 |
| 预算使用率 | 设置预算的用户占比 | ≥ 30% |

## 10. 风险与待确认事项

| 风险 / 待确认 | 说明 | 建议 |
| --- | --- | --- |
| 产品命名 | 「财务管家」为暂定名 | 确认最终名称，避免与现有产品重名 |
| 账号注册方式 | 验证码登录依赖短信/邮件服务，有成本 | V1 确认短信服务商，或先做邮箱验证码降本 |
| 小微需求泛化 | 覆盖经营场景易让 V1 失焦 | 坚持 V1 只做个人闭环，经营走 V2，靠自定义分类+导出暂时代偿 |
| 共享账本复杂度 | 多成员权限、分摊规则复杂 | V1 不做，V1.x 单独立项 |
| 数据安全合规 | 涉及个人财务敏感数据 | 明确隐私政策，数据加密，支持注销与导出 |

## 附：V1 验收标准（DoD）

1. 用户能用手机号/邮箱注册登录，换设备后数据一致。
2. 3 步内完成一笔支出，保存后首页数据即时更新。
3. 支持收入、支出、转账三类流水。
4. 可自定义账户与分类，账单可筛选、搜索。
5. 统计页能看到总览、分类占比、趋势，图表随筛选联动。
6. 可设置总预算与分类预算，超支有提醒。
7. 可按时间范围导出 CSV / Excel。
8. 手机浏览器（iOS Safari / Android Chrome）体验达标，首屏 ≤ 2s。
